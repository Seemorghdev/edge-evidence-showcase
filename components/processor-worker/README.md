# processor-worker

`processor-worker` is a standalone, bounded processing catch-up product generated
from private canonical source (identity withheld).

This repository is a **generated product**. Authoritative changes are upstream-first
and arrive through deterministic regeneration. Generated bytes do not carry the
private repository name, URL, branch, source commit, pull request, evidence path, or
operational coordinates.

## Product role

Capture, processing, and replication authority remain separate. This worker owns only
deterministic local processing catch-up:

1. inspect the existing SQLite and spool authority;
2. freeze the currently eligible raw-artifact snapshot;
3. process only that bounded snapshot;
4. verify or adopt deterministic derived output and lineage;
5. return a machine-readable summary.

It does not capture media, schedule future work, run as a daemon, publish events,
replicate evidence, provision infrastructure, expose an operator API, or create a
second authority.

## Authority and state transitions

The existing SQLite ledger and spool remain authoritative.

- `MISSING` means an eligible raw artifact has no deterministic processing job.
- `PREPARED` means the deterministic job exists and is safe to resume.
- `COMPLETE` means the derived metadata artifact and one-parent lineage are verified.
- Spool-lock contention is returned as `deferred`.

Exact retries do not create duplicate jobs or outputs.

## Codespaces and local setup

The development container installs Python 3.12, `ffmpeg`, `ffprobe`, `make`, and
SQLite tools, then runs the idempotent setup script automatically. In Codespaces,
open the repository and run:

```text
make demo
make inspect
```

For a local machine with Python 3.12 or newer, `ffmpeg`, `ffprobe`, and `make`:

```text
bash scripts/setup.sh
make demo
make test
make inspect
```

The setup script creates `.venv/`, installs the generated product in editable mode,
and performs `pip check`. Runtime Python dependencies remain empty.

## Make interface

- `make demo` recreates all three deterministic synthetic scenarios and retains their
  state under `.demo-output/`.
- `make test` runs the complete generated-candidate test suite.
- `make inspect` prints the retained database, spool, receipt, report, manifest, and
  summary structure without changing it.
- `make clean` removes only `.demo-output/`.

The ordinary worker interface remains:

```text
processor-worker run --database PATH --spool-root PATH
```

A successful invocation emits one compact JSON object with the frozen fields
`status`, `snapshot_eligible`, `already_complete`, `prepared_resumed`,
`newly_completed`, `deferred`, and `remaining`.

## Reliability demonstration

`make demo` uses the real exported processor worker and current canonical processing,
checkpoint, SQLite, filesystem, and lock contracts. It uses synthetic MP4 input only
and requires no network, credentials, external service, model, or publication action.

The aggregate proof class is `standalone_synthetic_processing_reliability` and covers:

### Normal processing

A fresh schema version 10 authority is populated with one deterministic synthetic raw
artifact. The real worker creates and verifies the derived report, manifest, metadata
artifact, processing job, and one-parent lineage. An exact replay proves idempotent
adoption with no duplicate authority.

### Interruption and resume

A child process is stopped immediately after the real `PREPARED` transaction commits.
The retained database proves the deterministic job exists while metadata and lineage
remain absent. A normal worker run resumes that same job, completes the remaining
work, and an exact replay proves no duplication.

### Busy-lock behavior

The demonstration acquires the real exclusive spool lock, runs the worker in a child
process, and records the expected `deferred` summary with zero database writes. After
release, the same worker succeeds and an exact replay remains a no-op.

run.

## Bounded-agent contract surface

The generated product includes `packages.agent_contracts`, the framework-neutral
contract surface for typed observations, deterministic classifications, bounded
proposals, policy decisions, verification outcomes, and structured receipts.

The processor example is model-free and read-only. It does not execute the worker,
write SQLite, mutate the spool, schedule work, contact a provider, or create a second
authority.

```text
python -m pytest -q tests/test_agent_contracts.py
```

## Optional read-only processor pilot

The conditional pilot is a separate installable distribution under
`optional/processor-pilot/`. The mandatory base installation does not expose a
`processor-pilot` command.

```text
python -m pip install -e './optional/processor-pilot'
processor-pilot --database PATH --canonical-commit 0000000000000000000000000000000000000000
python demo/run_pilot_demo.py
```

The all-zero value is a public redaction sentinel, not a private source commit. The
pilot remains read-only. The exact private source binding remains private validation
material.

Read-only ADK integration for inspecting and explaining processor state.

The optional offline ADK projection remains outside the mandatory worker install and
does not perform a model call, credential lookup, provider call, mutation, worker
execution, scheduling, deployment, or publication.

## Packaging and provenance boundary

The export contains the real worker and its minimum reviewed dependency closure,
including schema-v10 migration code. It excludes deployment roots, infrastructure,
private configuration, credentials, and private proof material.

## Provenance and reproducibility

`EXPORT_PROVENANCE.json` contains only schema/exporter version, component, the
`generated-product/upstream-first` policy, redacted public source label, exact
candidate path count, public-safe content digest, public license,
dependency-boundary identity, and verification commands.

Two candidates from the same exact private head must have identical paths, modes,
bytes, content digest, and deterministic one-commit disposable histories. Exact
private source binding is retained only in private validation records.
